# M3 报告：保障报价 + 转人工工单

日期：2026-11-21 · 测试：49 passed（模拟模型下）

## 1. 保障报价（`app/tools/protection.py`）
按订单动态定价（模拟），每个因子都返回，报价可解释、可审计：

| 产品 | 影响价格的因子 | "值得考虑"的判断规则（规则，不是 LLM 的意见） |
|---|---|---|
| Return Assurance | 品类基础费率、final sale +1%、商家退货窗口 ≤14 天 +1% | final sale / 美妆开封不可退 / 窗口短 / 国际退货自付运费 |
| Delivery Protection | 基础 1.2%、线路风险（低/中/高）、旺季 +0.5%、易碎品 +1% | 高风险线路或旺季、易碎、货值 ≥ $200 |

- 价格夹在 [$0.99, 6% 货值] 之间（与条款一致）。
- **货值 < $30 时两个都标"可能不值得"**：不硬推。
- 主动触达：推荐结果里有 final sale、高延误风险或货值 ≥ $200 的商品时，只给一个快捷按钮"Is protection worth it for #N?"，不在正文里推销。
- 永远说明"只能在结账时加购，理赔需要审核"。

## 2. 转人工（`app/tools/tickets.py` + `n_handoff`）
- 识别问题类型（丢件/损坏/延误/发错/退款），提取订单号；**没有订单号只问一次**，用户说"找不到"也照样开单。
- 工单摘要由代码确定性生成（不靠 LLM），写库前做 PII 脱敏。
- 丢件/损坏会附上 Delivery Protection 条款（带引用），但**绝不承诺退款/补发**。

### 幂等设计（这里踩过一个坑）
| 层 | 防什么 | key |
|---|---|---|
| Gateway 幂等键 | 同一个请求的重试（例如超时重发） | `session:request_id` |
| 工单服务去重 | 同一个问题投诉两次 | 一个会话 + 问题类型 + 订单号 只允许一张 open 工单 |

最初把幂等键设成了 `session:issue:order`，结果用户第二次催促时 gateway 直接返回缓存，回复又说一遍"我已为你开单"。
修正后语义分开：**重试 = 同一次创建**；**再次投诉 = 提示已有工单**。
测试覆盖了最难的情况：工单已写库但响应丢失 → gateway 重试 → 仍然只有 1 张，且对用户说的是"已开单"而不是"已有工单"。

## 3. 本轮自测发现并修复的问题
1. `#1` 无法识别为引用（正则 `\b` 在 `#` 前失效）。
2. "what about the cheapest one?" 丢失话题 → 新增话题延续（上一轮是保障/物流/政策问题，且本轮只是换了指代对象）。
3. "organic cotton tee final sale to Germany" 被当成政策问题 → 政策意图需要疑问语气或无商品信号。
4. 用户催单被判为闲聊 → 补充 "still nothing arrived" 等表达，命中已有工单。

## 4. 新增护栏
"Don't worry, you'll get your money back" / "Your refund will be processed" / "We'll send you a replacement" 都会被拦截（测试中用一个"会撒谎的模型"验证：拦截 → 重写 → 仍违规 → 模板兜底，工单卡片照常展示）。
