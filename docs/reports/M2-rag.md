# M2 报告：RAG 检索层

日期：2026-11-21 · Prompt 版本：2026-11-21.2

## 1. 做了什么

| 模块 | 内容 |
|---|---|
| 知识切分 | 49 个可引用片段，ID 稳定（`policy:maple#final-sale`）：5 家商家退货政策、保障条款、FAQ、跨境规则（10 国 + 3 条禁限运 + 旺季） |
| 检索 | BM25（词级）+ 字符 4-gram TF-IDF（抗词形变化/错拼），RRF 融合；元数据过滤（按商家/文档类型）；置信度门槛（都不像就不给模型喂噪声） |
| 作用域 | 政策问题先确定"哪家店"：指代的商品 → 明说的店名 → 已推荐商品都来自同一家；都推不出来就追问，回答后**恢复原问题**继续 |
| 引用 | 回答必须 `[n]` 引用；最终输出按出现顺序重编号，App 里可展开看原文 |
| 落地检查 | 无引用 / 引用不存在 / 数字（天数、金额、百分比）在原文里找不到 → 拦截，重写一次，再不过就用原文模板 |
| 降级 | 检索挂了 → 明确说"查不到，不想乱猜"，**绝不让模型凭记忆回答政策** |
| Seel 业务钩子 | 商家政策说"不能退"（final sale / 已开封）时，附带 Return Assurance 条款，并强调"仅当下单时已加购" |

## 2. 检索评测

| 数据集 | 条数 | 模式 | Recall@1 | Recall@5 | MRR |
|---|---|---|---|---|---|
| 开发集（调参前） | 40 | hybrid | 0.675 | 0.950 | 0.780 |
| 开发集（调参后） | 40 | bm25 / char / **hybrid** | 0.850 / 0.900 / **0.925** | 1.000 | **0.954** |
| **留出集**（调参后只跑一次） | 15 | bm25 / char / **hybrid** | 0.467 / 0.533 / **0.467** | 1.000 | **0.700** |

报告文件：`evals/reports/retrieval-*.json`、`evals/reports/retrieval_holdout-*.json`

### 结论（重要）
1. **开发集上的 Recall@1 提升大部分是过拟合**：同义词表是看着开发集的失败用例补的，留出集 R@1 只有 0.467。
2. **Recall@5 在两个集合上都是 1.0**，所以设计上不依赖第一条：给模型 top-4 让它自己读；不经过模型的降级模板展示 top-2。
3. 调参中修掉的真实缺陷（不是过拟合）：同义词原本是双向的（`return→refund`），把"退货期限"问题顶到了"退款时效"段落；改成"口语 → 知识库用语"的单向扩展，且原 query 权重加倍。
4. 留出集**不再用于调参**，否则它也会被污染。下一次检索改动（例如加 embedding 或 LLM 重排）用它来验收。

## 3. 已知问题 / 下一步候选
- 留出集 R@1 低：候选方案 ① 加 embedding 作为第三路融合信号 ② 用小模型对 top-4 做重排。需要先接上真实 API 才能评估。
- "what happens if my parcel is lost" 排第一的是"海关扣件" FAQ 而不是 Delivery Protection（top-2 内有正确答案）。
- 仍是 `unsupported_yet` 的场景：订单问题（丢件/损坏）→ M3 转人工工单。
